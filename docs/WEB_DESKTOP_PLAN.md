# QC 스튜디오 웹·Windows 전환 기획

작성/갱신: 2026-09-09. 상태: **일반 기준 우선 구현·통합 검증 중 / 내부 시험 패키지 생성, 정식 배포 전**.
현재 프로젝트는 ARCH_QA_SYSTEM이며 클레임센터 ES 산출프로그램과 별개다.
거래명세표 원가관리 프로그램은 화면 구성 참고용이다. 그 업무 필드·계산식을 가져오지 않는다.

## 1. 목표와 현재 출발점

회원 전용 Windows 분석 앱이 큰 산출서와 도면을 로컬에서 처리하고,
웹은 공용 프로젝트·지침·결과·권한 관리 창구로 유지한다. 서버 CPU 제한을
피하려고 검사를 없애거나, 웹 주소를 EXE 창에 넣는 것만으로 끝내지 않는다.

- 현재 브랜치 main, HEAD 33e3c06. 기존 배포 작업의 미커밋·미추적 변경 다수 존재.
- 현재 배포 기록: 7062a9a0-65cf-408f-8c83-1859265c1b51.
  기록 근거: `qa/2026-09-09-drive-registration-release.md`. 이번 기획에서 재배포하지 않음.
- 회사 Drive 분할 등록/다운로드는 구현됐으나 새 XLSX/CSV는 inspection_pending.
  안전한 파싱·매핑·검수 연결이 다음 우선 과제다.
- 기존 순수 TypeScript 파서·검수 엔진·보고서 로직을 재사용하고 운영 웹은 유지한다.
- 설치형 인증은 메모리 세션 방식으로 구현·검증 중이다. 자동 동기화, 회사별 기준서 해석, 자동 업데이트는 미완료다.
- 기존 PRODUCT/DESIGN의 Sites/R2·사이드바 중심 설명은 과거 상태를 포함한다.
  실제 배포 코드와 최신 결정 기록이 우선이며, 본 문서는 새 데스크톱 방향의 초안이다.

## 3. 설치형 기술과 보안 경계

**우선 후보: Electron + 기존 React/TypeScript + Windows NSIS Setup.exe.**
기존 TS 파서/계산 코드 재사용과 별도 Node 작업 프로세스 운용이 선정 이유다.
Tauri도 가능하지만 Rust 브리지와 JS 파서 실행 경계를 추가 검증해야 한다.
최종 버전 고정은 의존성 라이선스·유지보수·Windows 빌드 시험 후 결정한다.
현재 초기 구현은 Electron 44.3.0 / electron-builder 26.15.3을 사용한다.

- 화면은 패키지에 포함된 로컬 자원으로 구성한다. 임의 원격 페이지에 파일 권한을 주지 않는다.
- 화면의 Node 직접 접근 금지, contextIsolation/sandbox 유지, 최소 명령만 IPC로 노출한다.
- 파일 선택 후 발급한 내부 핸들로만 읽는다. 화면에서 임의 경로나 셸 명령을 전달하지 않는다.
- 파싱은 주 UI 프로세스와 분리하고 CPU·메모리·압축 팽창·시간 제한을 둔다.
- 매크로, 외부 링크, 임의 코드·Excel 수식 실행을 허용하지 않는다. 승인한 식 문법만 해석한다.
- 공용 AI 키·Google refresh token·DB 관리자 키는 서버에만 둔다.
- 초기 로그인 세션은 메모리에만 보관한다. 영속 로그인은 후속 OS 보호 저장소 설계이며 비밀번호는 저장하지 않는다.
- 로컬 작업 파일은 사용자별 앱 데이터 영역에 두고 PC 절대 경로를 서버 공용 경로로 저장하지 않는다.
- 설치 앱을 수정한 사용자가 결과를 위조할 수 있다는 경계를 전제한다.
  앱 결과 제출을 서버 검증/사람 승인과 동일시하지 않는다. 서버는 범위·버전·형식 및
  계산 가능한 개별 근거를 제한된 배치로 검증하고, 검증하지 않은 범위를 표시한다.

## 4. 회원 로그인·권한

기존 지정 회원명단과 계정을 재사용한다. 공개 회원가입은 만들지 않는다.
관리자 계정은 yjw@con-cost.com, yjpark@con-cost.com 두 개뿐이다.
회사 관리자와 프로젝트 소유자/검수자/승인자/조회자의 권한은 별개로 유지한다.

현재 서버는 HttpOnly 세션 쿠키와 정확한 웹 Origin을 요구한다.
file:// 예외 허용이나 CORS 전면 해제로 설치 앱을 연결하지 않는다.
우선 설계는 시스템 브라우저에서 기존 회원 로그인 후 PKCE와 단회·단기 교환코드로
앱 세션을 발급하는 방식이다. 웹 로그인 상태와 앱 기기 세션을 구분하고 기기별 해제한다.
루프백 콜백은 127.0.0.1 임시 포트·state 검증·짧은 만료·1회 사용을 강제한다.

초기 정책안:
- 최초 실행, 새로운 프로젝트 접근, AI 검수·공유·지침 배포는 온라인 인증 필수.
- 네트워크 단절 시 진행 중 로컬 작업은 안전하게 임시 저장하고 신규 민감 작업은 대기.
- 장기 오프라인 이용권은 초기 범위에서 제외한다. 별도 승인 정책 없이 회원 차단을 우회하지 않는다.
- 로그아웃 시 메모리·세션을 정리하고 로컬 자료 보관/삭제 선택을 명확히 안내한다.
- 이미 내려받은 파일을 계정 차단만으로 원격 회수할 수 있다고 약속하지 않는다.

## 5. 데스크톱 화면 설계 — Operate

시각 기준은 사용자 제공 거래명세표 원가관리의 두 스크린샷이다.
넓은 흰 작업면, 얇은 경계, 짧은 도구 버튼, 상단 프로젝트 맥락, 목록·상세 분할을 따른다.
홍보용 대형 카드·장식 통계·과도한 여백은 넣지 않는다. 기존 QC 색상 역할을 유지한다.

├ 현재 프로젝트/전환 │ 건설사 │ 마감·구조 │ 적용 기준서 버전 │ 작업 상태 │ 저장·검수 실행 ┤

웹은 기존 화면을 당장 전면 교체하지 않고 공용 관리 기능부터 공유한다.

## 6. 후속 확장: 건설사별 검수 기준 관리

일반 검수 완성 후 제공하는 확장 기능이다. 아래는 확장 기능을 출시할 때의 요구사항이며
일반 기능 출시의 선행 조건이 아니다. 관리자 일반 지침 편집 요구는 별도로 유지한다.

### 6.1 관리자 작업 흐름

1. 건설사를 선택하거나 등록하고 기준서 제목·발행처·문서일·개정번호·적용 범위를 입력한다.
2. 산출기준서 원본을 첨부한다. 해시와 버전을 고정하고 기존 원본을 덮어쓰지 않는다.
3. 문서의 조항·표·수식·예외를 추출하고 페이지/절/표 위치를 연결한다.
4. AI가 검사 항목 초안을 제안한다. 원문에 없는 임계값·단위·판정 조건은 만들지 않는다.
5. 관리자가 원문과 추출 내용을 나란히 보고 조건·예외·필요 자료를 수정한다.
6. 합성 또는 승인된 시험 자료로 적합/불일치/예외/근거 부족 사례를 시험한다.
7. 변경 차이와 영향 프로젝트를 확인한 뒤 승인·게시한다.
8. 프로젝트에 적용할 기준 패키지 버전을 명시적으로 선택한다.

초기 자동 추출 대상은 텍스트 PDF/DOCX를 우선 검증한다. 스캔 PDF는 OCR 품질 확인이
필요하며, HWP/HWPX·복잡한 수식/도표는 전용 파서 또는 승인된 변환 경로를 검증하기 전
자동 지원으로 표시하지 않는다. 읽지 못한 페이지는 추출 완료로 처리하지 않는다.
기준서 문장은 앱 정책을 바꾸는 명령이 아니라 **검토할 문서 데이터**로 취급한다.

### 6.2 검수 항목 편집 필드

| 묶음 | 필요한 필드 |
|---|---|
| 식별 | 항목 ID, 제목, 건설사, 공종, 개정 버전, 활성 여부 |
| 근거 | 기준서 버전/해시, 페이지·절·표, 원문 인용, 추출 상태 |
| 대상 | 동·층·부위·재료·규격·단위·적용 기간/프로젝트 조건 |
| 입력 | 필요한 산출서/집계표/도면/셀, 각 값의 의미와 단위 |
| 검사 | 검사 종류, 비교식, 공제/할증/반올림 조건, 허용오차와 출처 |
| 예외 | 제외 조건, 특수 부위, 승인된 프로젝트 예외와 이유 |
| 결과 | 수준 A/B/C, 중요도, 표시 문구, 필요한 증거, 판정 불가 사유 |
| 운영 | 작성자, 시험 사례, 승인자·시각, 적용 프로젝트, 폐기 사유 |

**임계값은 입력 사례에서도 임의 숫자로 채우지 않는다.** 예를 들어
“개구부 공제 기준 준수”는 해당 기준서가 정의한 면적·공제 방식·예외를 확인한 뒤
구성한다. 기준이 누락되면 항목을 초안/보류 상태로 둔다.

### 6.3 관리자가 코드 수정 없이 바꿀 수 있는 것

- 항목 추가/복사/비활성, 적용 조건과 예외, 기준값·허용오차, 근거 조항, AI 검토 문장.
- 승인된 연산자 목록 안에서 조건을 조합한다. 단위와 입력 형식을 검사한다.
- 자연어만으로 계산 규칙을 자동 확정하지 않는다. AI는 구조화된 초안을 제안한다.
- 새 연산자·새 CAD 형식·새 계산 알고리즘은 개발 및 앱 업데이트가 필요하다고 표시한다.
  “어떤 조건이든 문장만 넣으면 정확히 처리한다”는 약속은 하지 않는다.
- 임의 JavaScript/Python/SQL 실행, eval, 사용자 코드 플러그인은 초기 범위에서 금지한다.

### 6.4 기준의 조합·충돌

공통 기준, 건설사 기준, 프로젝트 특약, 승인 예외를 별도 층으로 보관한다.
이름이나 문서 날짜만으로 우선순위를 추정하지 않는다. 충돌 시 관리자가 근거를
남겨 해당 프로젝트의 우선 기준을 확정한다. 미해결 충돌은 관련 항목을 보류한다.
다른 독립 항목의 검수는 진행할 수 있다. 다른 건설사의 기준을 검색/AI 문맥에 섞지 않는다.

상태: 초안 → 원문 확인 → 시험 → 승인·게시 → 대체/폐기.
게시본은 불변이다. 수정은 새 버전으로 만들고, 새 버전을 기존 프로젝트에 자동 강제 적용하지 않는다.
실행 시작 시 기준서·규칙·예외·파서·엔진·원본·매핑 버전을 고정한다.
지침 변경 중 실행은 기존 스냅샷을 유지하고 재검수는 별도 실행으로 남긴다.

### 6.5 산출기준서 준수 결과

각 결과에 규칙 ID/버전, 원본 파일·시트·셀, 기준서 페이지·조항,
관측값·기준값·단위·차이, 적용 조건·제외 사유, 실행 ID, 사람 판단을 표시한다.

- 적합: 실제 비교를 수행했고 해당 검사 조건을 만족함.
- 불일치: 승인된 결정론 규칙으로 차이를 재현함.
- 검토 필요: AI 해석/문맥 또는 사람 판단이 필요함.
- 근거 부족: 도면·치수·매핑·기준 문구 등 필요한 입력이 없음.
- 적용 제외: 승인된 범위/예외에 해당함.
- 실행 실패: 파싱/API/작업 실패. 적합이나 0건으로 바꾸지 않음.

보고서에는 승인된 검사 항목 수, 실제 평가 수, 제외·근거 부족·실패 수와
기준서 미추출 페이지 범위를 함께 표시한다. 평가한 일부만으로 전체 준수를 선언하지 않는다.
AI 후보는 원본 수량 수정·자동 승인·자동 종결을 하지 않는다.

## 7. 로컬 처리·동기화·여러 PC

로컬 저장과 서버 저장을 분리해서 표시한다. 데이터의 기준 저장소는 공용 메타데이터의 경우
서버이며, 아직 동기화하지 않은 작업은 해당 PC에만 있다는 사실을 명시한다.
초기 버전은 실시간 공동 편집 대신 버전 기반 저장·충돌 확인을 사용한다.

- 원본 ID/해시·작업 ID·기기 ID·서버 버전을 사용한다. 파일 이름만으로 같은 원본이라 판단하지 않는다.
- 로컬 작업 상태: 선택 → 안전 검사 → 파싱 → 매핑 확인 → 검수 → 출력 준비.
- 별도 동기화 상태: 로컬 전용 → 대기 → 전송 중 → 서버 확인 → 충돌/실패.
- 서버 확인 전에 공유 완료 표시 금지. 네트워크 재시도는 같은 요청 ID로 중복 생성을 막는다.
- 두 PC가 같은 매핑/지침을 편집하면 이전 버전 번호로 충돌을 검출하고 양쪽 내용을 보존한다.
- 보고서와 검수 실행은 덮어쓰지 않는다. 변경한 매핑/지침은 새 실행으로 연결한다.
- 작업 중 종료/충돌 시 원본·저장된 체크포인트를 기준으로 복구한다.

## 8. AI 처리량·비용과 원본 보관

전체 원본을 매번 AI에 보내지 않는다. 기준서는 한 번 추출한 조항을 버전별로 보관하고,
해당 공종·항목에 필요한 조항과 최소 산출 데이터만 선택해 요청한다.
프로젝트/건설사 권한 필터를 AI 검색 전 강제한다. 해시+매핑+규칙+모델/프롬프트 버전이
같은 작업만 재사용 후보로 삼으며 이전 실패나 미평가를 성공 캐시로 재사용하지 않는다.

실행 전 대상 항목·행·기준 조항·예상 토큰·설정된 상한을 보여 준다.
가격표를 확인하지 못하면 금액은 미확인으로 표시한다. 상한 초과 시 무단 추가 호출 대신 대기한다.
청크별 처리량과 실제 usage를 남기며 실행 실패 시 이미 과금된 호출이 있을 수 있음을 안내한다.

보관 정책:
- 원본 공유는 선택 가능, 최종 분석표·검수 근거·승인 이력은 별도 보관.
- 목록에서 제거/휴지통 이동/실제 Drive 원본 삭제/로컬 사본 삭제를 다른 동작으로 구분.
- 보고서 저장과 복구 가능 여부 확인 전에 원본 자동 삭제하지 않음.
- 실제 삭제 전 대상 파일·영향받는 재검수/원문 열람·보존 근거를 확인하고 감사 기록 남김.
- Drive 휴지통 이동을 즉시 용량 반환으로 약속하지 않음. 실제 용량 정책은 구현 시 확인.
- 원본을 삭제한 보고서는 원문 재현 제한을 표시하고, 재업로드 시 해시 일치 여부로 연결.

## 9. 설치·온라인 업데이트·3대 PC 인수인계

설치물 이름 예: CONCOST-QC-Setup-x.y.z.exe. 배포 채널은 내부 시험/정식으로 분리한다.

  DB가 바뀌었다면 이전 EXE만 실행하는 것을 안전한 롤백으로 간주하지 않는다.
- source commit, lockfile, 앱 버전, API 버전, migration, 설치물 SHA256, 테스트 결과를 릴리스 기록에 묶음.
