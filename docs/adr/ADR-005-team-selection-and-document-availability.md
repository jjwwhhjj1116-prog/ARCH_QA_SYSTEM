# ADR-005: 팀 선택과 자료 가용성 안내

- Status: accepted
- Date: 2026-09-03
- Owners: Main / Platform reviewer
- Related acceptance IDs: UI-001, UI-003, UI-005, A11Y-005

## Context

기존 `+ 마감팀`은 클릭할 때마다 새 검수 케이스를 생성했다. 사용자는 케이스 관리가 아니라 팀을 선택해 자료를 등록하고, 부족한 자료를 확인하면서 가능한 범위의 검수를 진행하기를 요청했다.

## Verified facts

- FIN 6.2 사용자 설명서 100–106쪽의 집계 옵션 및 조회 종류를 로컬 추출본에서 확인했다. 공종별·동별·층별·실별·세대별 조회와 산출근거 추적을 안내한다.
- 원본 위치: `CONCOST_BRIDGE_V1.0/Docs/마감물량산출(ver 6.2) 사용자 설명서.pdf`. 추출본은 로컬 `fin-analysis/tmp/fin62_manual_text.txt`이며 고객 파일은 저장소에 복사하지 않았다.
- 부위별집계표는 해당 매뉴얼 절에서 필수 종류로 확인되지 않아 실제 양식을 확인할 보조 자료로 구분한다.
- 기존 case ID는 원본 파일 계보에 연결되어 있으므로 UI 정리를 위해 삭제하거나 자동 병합하면 안 된다.

## Options

1. 기존 케이스 생성 UI 유지: 계보는 유지하지만 같은 팀이 반복 생성되는 혼란이 지속된다.
2. 기존 API와 계보를 유지하고 팀 선택 UI로 변경: 저장소 변경 없이 현재 요구에 대응한다. 여러 탭에서 동시에 첫 생성하는 경쟁 조건은 별도 서버 작업으로 남는다.

## Decision

2번을 채택한다. 같은 팀의 활성 기록이 있으면 재사용하며, 과거 동일 팀 기록은 드롭다운으로 보존한다. 단일 화면의 연속 클릭은 동기 ref로 차단한다. 새 팀 생성 실패 시 기존 미저장 파일 선택을 보존하고 확인창은 한 번만 표시한다.

파일명 체크리스트는 제출 안내이며 파서·AI 검수 결과가 아니다. 모든 종류를 필수로 요구하지 않는다. 차단·거절·삭제 상태 또는 프로젝트 충돌인 묶음은 제외하고, 서버에서 `stored`로 확인된 파일이 하나 이상 있을 때만 다음 단계 진입을 허용한다. 일부 저장된 묶음의 서버 상태를 전체 성공으로 승격하지 않는다. 로딩·저장·오류 중에는 다음 단계 버튼을 잠근다.

## Consequences

- 기존 파일·케이스·감사 기록을 삭제하지 않는다. D1/R2 스키마 및 인증 변경도 없다.
- 파일명만으로 분류할 수 없는 자료는 별도로 표시하며 저장을 막지 않는다. 실제 분석은 입력 매핑 및 검수 엔진 연결이 필요하다.
- 서버 측 팀 단일성 제약은 추가하지 않았다. 여러 탭에서 최초 팀 생성이 동시에 발생하는 문제는 후속 get-or-create API 작업 범위다.
- 같은 팀의 여러 과거 기록을 한 분석 입력으로 합치는 기능도 이번 변경에 포함하지 않는다.
- 롤백은 이전 소스 배포로 가능하며 데이터 마이그레이션은 필요하지 않다.

## Validation

팀 재선택 시 POST 1회, 기존 기록 드롭다운, 부분 저장 진행, 빈 기록 전환 시 단계 잠금, 팀 생성 실패 시 선택 보존 및 확인 1회, 충돌·차단 제외를 자동 테스트한다. 새 브라우저 시각 검증 및 고객 자료의 실제 AI 분석은 이번 검증에 포함하지 않는다.
