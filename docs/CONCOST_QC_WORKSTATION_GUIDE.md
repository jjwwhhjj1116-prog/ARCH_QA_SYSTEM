# FIN 검수 작업실 — 사용 순서와 구현 경계

2026-09-07. 이번 배포는 FIN 핵심 검수 작업실의 1차 구현이다. 실제 FIN 출력물 전체에 대한 정확도 인증이나 20개 검수 지침 전체의 완성을 뜻하지 않는다.

## 사용하는 순서

1. 왼쪽에서 프로젝트를 추가하거나 선택한다. 마감팀을 선택하고 자료를 올린다. 업로드 영역 **맨 위**에서 저장·다음 단계 이동을 한다. 수정본은 기존 자료 교체를 선택한다. 교체 완료 전에는 이전 자료가 유지되며 이력은 삭제하지 않는다.
2. STEP 2 상단의 **자료 자동 확인·저장**을 한 번 누른다. 표준 FIN 산출서(알려진 6·7·8·9열)와 동별집계표는 파일명뿐 아니라 실제 표제·머리글·내용을 확인하여 열 연결을 한 번에 저장한다. 기존 수동 연결은 덮어쓰지 않는다. 읽기 실패·비표준 시트만 목록에서 확인하고 필요할 때 **열 연결 직접 수정**을 펼친다. 열 구조 인식은 수량 의미 확인이 아니다. 물량이 표시 산식의 직접 결과인지 확인하지 않으면 산술 검사를 실행하지 않는다.
3. 치수 패턴 검사는 별도 치수 열, 치수 의미/단위, 동일 실 유형·부위·산출 방식을 구분하는 비교집단 열을 확인해야 한다. 식의 첫 숫자를 길이로 임의 해석하지 않는다. 이런 정보가 없는 FIN 출력물은 추가 매핑 개발 대상이다.
4. 일반 검수자는 승인된 지침으로 상단 **검수 실행**을 누른다. 지침 초안·시험은 일반 검수 단계에 없다. **산출식 AI 검수 / 중복 ITEM AI 검수**를 선택하면 제목·설명·결과·평가 범위가 함께 바뀐다. 중복 화면은 동별집계표 ITEM-018 후보만, 산출식 화면은 산식·치수 결과만 표시한다. 실행 이력과 원본은 같은 불변 스냅샷을 사용한다.
5. 관리자(workspace_admin 또는 project_owner)만 왼쪽 **설정 → 검수 지침 관리 · 관리자**에서 허용오차·비교 표본·예외를 작성하고 시험 후 활성화한다. 일반 검수는 최신 초안이 아닌 승인 버전을 사용한다. 초깃값 0.01, 5개, 15%는 시험용이지 업계 기준이 아니다. 지침 활성화는 보고서 최종 승인이나 오류 확정이 아니다. 소유자 개인 시험 환경에서는 작성한 지침을 직접 활성화할 수 있지만 보고서 자기승인은 구현/허용하지 않는다.
6. 정식 검수 후 목록 → 원본 행 → 근거·비교 항목을 확인한다. 수정 필요/정상 항목/보류와 사유를 저장한다. 원본은 고치지 않는다. 정정 판단은 새 이력으로 남는다. 비관리자는 지침 초안·시험 실행을 조회하거나 직접 API로 작성·시험·승인할 수 없다.
7. 실행 이력에서 다시 열거나 XLSX 보고서(검수 결과·범위/제한·판단 이력)를 내려받는다. 지침 변경·재검수는 새 버전/실행이고 과거 결과는 유지된다.

## 실행되는 규칙

| ID        | 판단                    | 필요한 근거                                           | 검증 사례                                                        |
| --------- | ----------------------- | ----------------------------------------------------- | ---------------------------------------------------------------- |
| CALC-007  | A / 산술 불일치         | 직접 산식 결과임을 확인한 숫자 물량·단위              | 10×3과 기재31은 불일치; 100×3×2=600은 산술 정상                  |
| PARSE-008 | A / 검수 불가           | 미정의 변수·셀 참조·함수                              | H×10, SUM(A1:A2)는 계산하지 않고 미평가                          |
| DIM-001   | B / 소수점 의심         | 확인된 양수 치수·역할·단위, 동일 비교집단의 다른 표본 | 10 근방 5개와100은 후보10; 모두100·0기준·부위차이는 오탐 방지    |
| DIM-RANGE | B / 기준 범위 의심      | 사용자가 설정한 역할·단위·최소/최대                   | 동일 역할/단위에서만 검사; 기준 없으면 미평가                    |
| ITEM-018  | C / 중복·공종 분산 후보 | 동별집계표의 품명·규격·단위·부위·코드·공종            | 미장/금속공사에 같은 아이템, 다른코드 후보; 다른단위/부위는 분리 |

ITEM-018은 현재 정규화된 동일 표기 비교다. 베트남어/오탈자/동의어의 의미 비교는 아직 수행하지 않는다. 자동 병합·합산·공종 확정은 하지 않는다. 공종 구분행은 두 자리 코드 + 공사/공종 명칭 + 빈 규격/단위로 인식하고 근거 셀을 보존한다. 다른 양식의 공종 계층은 수동 매핑/추가 파서가 필요하다.

## 아직 수행하지 않는 것

사용자 제안 20개 중 두께 규격 대조, 단위 환산 추론, 반복 개소/층수 중복, 창호 공제, 환산·할증 단계, 상세/집계 교차 대조, 반복층 편차, 마감면적 정합, 개정 전후 행 연결은 추가 개발·실제 자료 검증이 필요하다. 원본 교체와 과거 실행 열기는 가능하지만 해결/신규 경고의 자동 대응표는 아직 없다. RC·조적·분석표 개요는 후속 범위다.

Gemini 설정의 연결 시험과 결정론적 검수 실행은 별개다. 현재 검수 엔진은 외부 AI 호출 없이 계산/패턴/동일표기 후보를 만든다. 자연어 지침 생성·임의 수치 보정·도면 대조·CAD 실행을 완료 기능처럼 표시하지 않는다.

## 안전 한도와 이력

업로드·검수 원본은 20MiB까지 읽는다. 종전 XML 8MiB 일괄 해제 방식은 행 단위 스트리밍으로 바뀌었다. 선택 XML 64MiB/읽기 패스, 공유 문자열·펼친 셀 각각 4MiB, XML 조각 512KiB, 파일당 내용행 12,000/물리행 200,000/30시트/256열의 안전 한도를 둔다. 서식만 있는 빈 행은 내용행 한도에 포함하지 않고 실제 원본 행번호는 보존한다. 압축·XML 구조·주소·DTD·엔티티 검사는 유지한다. 실행20,000행 및 원본 근거10MiB, 결과 근거6MiB/8,000건은 별도 한도다. 초과·해석 실패 자료를 정상으로 취급하지 않는다. 8MiB 초과 합성 파일 시험은 통과했지만 사용자 실제 대용량 파일과 배포 Workers의 처리 한도는 별도 검증이 필요하다.

D1에는 지침/매핑/실행/판단 메타데이터와 감사 기록, 비공개 R2에는 원본 및 해시 검증된 실행 스냅샷을 저장한다. 새로고침은 서버 이력을 읽는다. 브라우저 메모리에만 저장되는 데모 이력이 아니다. 실행 요청이 불명확하게 종료되면 이력 새로 확인 후 재시도한다. 동일 네트워크 요청의 완전한 멱등 재개는 후속 과제다.

## 변경 및 복구

ADR-007/008, migration 0005/0006을 따른다. 0006은 지침 작성·승인·시험을 관리자 전용 SQL 가드로 강화하며 기존 자료를 삭제하지 않는다. 이미 적용된 0005는 변경하지 않는다. 코드 롤백 시 테이블/R2 객체와 0006의 강화된 권한 가드를 보존한다. 구버전 UI에 보이는 비관리자 지침 버튼은 서버/DB에서 거부될 수 있다. 불변 이력 테이블은 직접 UPDATE/DELETE하지 않는다. 권한·활성 프로젝트·FIN 범위·매핑 충돌은 저장 시점에 다시 검사한다.

자료/지침/실행/판단의 API는 `/api/projects/:projectId/review`다. GET은 caseId와 선택 runId로 조회; POST action은 inspect, mapping(baseVersionId), profile, run(trial), approve(matching trial), decision(reason)이다. 모든 경로에 사용자·프로젝트·자료기록 범위를 확인한다. 자료 구조 변경 충돌409, 크기한도413, 형식보류422, 권한403을 구분한다.
