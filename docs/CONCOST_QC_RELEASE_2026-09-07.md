# CONCOST 기술본부 QC 스튜디오 — FIN 검수 작업실 릴리스 검증

## 범위와 판정

소유자 전용 파일럿이다. 실제 현장 산출서에 대한 정확도 인증·20개 지침 전체·최종 보고서 승인 기능의 완성을 의미하지 않는다. 기존 전체 상용화 게이트를 통과했다고 표시하지 않는다. 사용자 요청에 따라 같은 비공개 주소에 배포하며 공개 범위를 확대하지 않는다.

밝은 단일 스타일 시트, 프로젝트 중심 탐색, 업로드 맨 위 저장/STEP 2, 원본 열 매핑, 조건/예외의 지침 버전, 시험→활성화→정식 실행, 목록/원본/근거 대조, 사람의 판단, 서버 이력, XLSX 보고서를 연결했다. 기존 수정본 교체 트랜잭션과 이전 이력은 보존했다.

## 근거

- 표준 lint/format/typecheck/unit/build와 신규 CSV/XML/규칙/SQLite 가드 시험을 수행했다. 실행 한도, 0/공란, 미해석 변수, 공종 헤더, 다른 부위/단위, 미승인 실행, 매핑 충돌, 불변 이력을 포함한다.
- 전체 로컬 D1 migration 0001~0005 적용 및 재실행 통과. 운영 의존성 audit: 취약점 0.
- 기존 브라우저 회귀: 1440, 1280, 768, 360 너비. 9 passed / 3 skipped(모바일 전용 시험의 비모바일 제외). 프로젝트 생성/팀 선택/자료 저장/상단 STEP 2/재선택 후 동일 기록 재사용, 권한 경계, 모바일 메뉴, axe WCAG A/AA 시험을 포함한다. 초기 대비·모바일 숨김·표 키보드 스크롤 문제를 수정한 뒤 재실행했다.
- 선택된 인앱 브라우저에서 합성 CSV 2개를 상단 버튼으로 실제 로컬 D1/R2에 저장했다. 상세/동별집계표를 각각 매핑하고 지침 v1 시험→활성화→정식 실행을 완료했다.
- 합성 18행에서 검토 4건: 소수점 의심 100→10, 산술 10×3≠31, H×10 해석 불가, 미장/금속공사의 서로 다른 코드 중복 후보. 정상 100m를 무조건 오류로 보거나 미평가를 정상으로 표시하지 않는다.
- 소수점 후보에 보류+사유를 저장하고 재조회에서 동일 판단 이력을 확인했다. 원본 J7, 비교 표본 5개, 원본 해시/지침/실행 버전 표시 확인.
- XLSX는 인증된 GET에서 동결 실행과 저장된 판단을 읽어 제공한다. 실제 로컬 응답 200, no-store, attachment, XLSX MIME, ZIP 서명 및 3개 워크시트 구조 검증. 초기 Blob 다운로드의 인앱 이벤트 확인이 안 되어 서버 다운로드로 변경했다. 브라우저의 다운로드 파일 저장 위치까지 검증한 것은 아니다.
- 시험은 합성자료만 사용했다. 실제 운영 프로젝트 생성/수정/삭제 시험은 하지 않았다.

## 독립 검토 및 재사용 스킬

FIN 도메인, 워크플로/권한, OSS/복잡도 검토를 세 서브에이전트에 분리했다. 발견된 요약행 혼입, 0 기준 비교, 공종 헤더, 조건 적용, 원본 셀, 역할/상태 변경, 매핑 경쟁, 입력/근거 크기 문제를 수정하고 회귀시험을 추가했다.

글로벌 스킬 `fin-source-mapping`, `fin-rule-evidence`, `qc-workstation-delivery`를 생성·설치·형식 검증했다. 사용 순서와 OSS 출처/라이선스는 `QC_SKILL_PIPELINE.md`를 따른다.

## 남은 정확도 경계

실제 FIN 변수/산식코드·병합 계층, 독립 기준정보, 환산/반복/공제/상세집계 교차검수, 다국어·오탈자 의미 비교, 개정 전후 해결/신규 경고 연결, 대형 비동기 처리, 최종 보고서 승인, RC/조적은 후속이다. Gemini 연결 시험이 검수 AI 호출 완료를 의미하지 않는다. 이번 엔진은 계산/조건/패턴/동일표기 비교를 사용한다.

업로드는 파일당 20MB이나 이번 동기 검수는 8MB 및 행/근거 크기 한도가 있다. 파일별 해석 제한은 미평가 사유로, 실행 전체 한도 초과는 중단·분할 안내로 표시한다. 상세 제한은 `CONCOST_QC_WORKSTATION_GUIDE.md`를 확인한다.

## 배포와 복구

첫 배포는 SQL `incomplete input`으로 실패했다. live DB overview에서 qc_* 테이블 5개가 모두 없음을 확인한 후, 아직 적용되지 않은 0005 파일에 Drizzle statement-breakpoint를 추가해 트리거 내부 세미콜론과 문장 경계를 구분했다. 이미 적용된 0001~0004는 수정하지 않았다. 새 SQLite 시험은 각 breakpoint를 하나의 prepare 문장으로 실행해 불변/권한 가드를 검증한다. 같은 실패 아카이브를 반복 배포하지 않는다.

검증 소스를 Sites 저장소에 push하고 같은 소스의 빌드를 패키징해 owner-private으로 배포한다. 공개 URL·빌드 표시·접근 상태의 최종 결과는 배포 도구 결과와 브라우저에서 별도로 확인한다. 코드 복구 시 이전 저장 버전으로 배포를 되돌리되 추가된 이력 테이블과 원본 R2 객체를 삭제하지 않는다.
