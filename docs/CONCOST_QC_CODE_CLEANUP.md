# CONCOST QC Studio — 코드 정리 및 자료 등록 개선

검증일: 2026-09-03

## Ponytail 적용

- 소스: https://github.com/DietrichGebert/ponytail
- 고정 버전: `2ed6c52c9d7e5e56942508591085fd45dea277d3` (4.9.0, MIT)
- 이 PC의 Codex 전역 스킬 폴더에 `ponytail`, `ponytail-review`, `ponytail-audit`, `ponytail-debt`, `ponytail-gain`, `ponytail-help`를 설치했다. 설치본과 고정 소스의 텍스트 일치 확인 및 MIT 라이선스 보존을 완료했다.
- 자동 실행 훅이나 전역 AGENTS 지침은 추가하지 않았다. 다른 PC·클라우드 환경까지 동기화하는 설치는 아니다.
- 사용처가 없어진 프로젝트 선택·후보·케이스 목록 CSS 505줄을 제거했다. 보안 검사, 권한 확인, 원본 보존, 테스트는 삭제하지 않았다.
- 중복된 자료 저장 준비 상태 판정을 `hasUsableStoredSources`로 모으고 필요한 동작 변경은 아래 테스트로 검증했다. 토큰 절약률·성능 향상 수치는 측정하지 않았으므로 주장하지 않는다.

## 함께 반영한 사용자 요청

- 설정·예시 카드의 어두운 회색 작업면을 파스텔 토큰으로 교체하고 어두운 본문색을 사용했다.
- 팀 선택 후 자료 업로드, 기존 같은 팀 기록 재사용, 과거 기록 선택 드롭다운을 적용했다.
- 파일명 기반 산출서·집계표 체크리스트와 FIN 6.2 매뉴얼의 집계 종류 설명을 추가했다.
- 일부 자료 누락은 진행을 막지 않되, 서버 저장 확인된 자료만 다음 단계 진입의 근거로 인정한다.
- 세부 결정 및 제한: [ADR-005](adr/ADR-005-team-selection-and-document-availability.md).

## 검증

- `npm run check`: lint, formatting, typecheck, 25개 테스트 파일의 148개 테스트, production build 모두 통과.
- 팀 중복 생성 방지, 기존 기록 보존, 부분 저장 진행, 빈 기록 전환 후 단계 잠금, 팀 생성 실패 시 미저장 파일 보존, 확인창 1회 동작을 검증했다.
- 신규 팔레트 토큰의 본문 대비 계산: 하늘색 12.12:1, 파란색 8.61:1, 분홍색 8.72:1. 이는 토큰값 계산이며 전체 화면의 실측 접근성 인증은 아니다.
- 플랫폼 읽기 전용 검토에서 새로운 보안·계보 blocker는 없었다. 검토 중 발견한 신규 팀 전환의 이중 확인창은 수정하고 회귀 테스트를 추가했다.
- 새 브라우저 시각 QA, E2E 실행, 실제 고객 파일 AI 검수는 이번 검증에 포함하지 않았다. 기존 E2E 기대 문구만 새 UI에 맞게 수정했다.
- D1/R2 스키마, 인증 계정, 외부 공개 범위 변경 없음. 기존 원본과 검수 기록 삭제 없음.

## 후속 수정 — 체크리스트와 좌측 프로젝트 관리

같은 날짜의 사용자 스크린샷과 브라우저 검증 승인에 따른 후속 작업이다. 위 148개 테스트 검증 이후의 변경 사항이며, 앞선 시각 검증 미실시 기록을 대체하지 않는다.

- 원인: `.selected-project li`의 진행 상태용 `22px 1fr` 그리드가 중첩된 체크리스트에도 적용되어 자료명과 상태가 한 글자씩 줄바꿈되었다. 이를 직접 자식 진행 목록으로 한정하고 체크리스트 행의 자료명·상태·설명 배치를 명시했다.
- 좌측의 추가 버튼 아래에서 프로젝트를 등록하고 각 프로젝트 옆 빨간색 `삭제`로 한 번 확인 후 목록에서 제거한다. 기존 생성·삭제 API와 공유 폼·대화상자를 재사용했다. 원본과 감사 이력을 보존하는 서버 정책은 변경하지 않았다.
- 생성/삭제 중 중복 요청과 파일 저장 중 프로젝트 변경을 방지한다. 삭제 취소·실패 때 현재 선택을 보존하고 삭제 성공 후 포커스를 왼쪽 추가 버튼으로 복귀시킨다.
- 모바일 중첩 패딩을 줄이고 삭제 대화상자를 가운데 배치했다. 버튼 여백과 최소 터치 영역을 확보했다.
- 사용자 지정 검수 기준: 동별집계표의 전체 아이템을 공종 간 대조한다. 공종 오배치 의심과 중복 후보를 구분하고 PM 확인 전 자동 이동·통합하지 않는다. 상세 기준은 `DESIGN.md`에 기록했다. 실제 AI 엔진이나 입력 매핑을 새로 구현한 변경은 아니다.

### 후속 검증

- `npm run check`: lint, formatting, typecheck, 25개 테스트 파일의 **152개 테스트**, production build 모두 통과.
- 추가 회귀 테스트: 왼쪽 등록과 기존 화면 유지, 삭제 취소·실패 재시도·현재 선택 초기화·포커스 복귀, 조회자 삭제 버튼 미노출, 동별집계표/공종 오배치 안내와 실행 불가 예시 구분.
- 승인된 로컬 브라우저에서 1280×900 및 360×800으로 실제 화면을 확인했다. 체크리스트 행이 세로 한 글자로 갈라지지 않고, 자료명/상태/설명이 정상 배치됐다. 모바일 최종 체크리스트 너비 276px, 문서 너비 352px로 360px 뷰포트의 가로 넘침이 없었다.
- 좌측에서 임시 프로젝트 2개를 생성해 팀 선택·업로드 화면 진입, 추가 창의 기존 작업 유지, 삭제 취소와 확인을 검증했다. 임시 프로젝트만 UI 삭제(보관 처리)했으며 기존 로컬 프로젝트와 운영 자료는 변경하지 않았다. 임시 뷰포트는 복원했다.
- 실제 고객 파일 업로드, 실제 AI 판정, E2E 스위트 전체 실행은 이번 검증에 포함하지 않았다. 인증·D1/R2·공개 범위 변경 및 스키마 마이그레이션 없음.

## 후속 수정 — 업로드 상단 STEP 2 바로가기

- 사용자 지정 위치인 업로드 제목 오른쪽, 닫기 버튼 왼쪽에 `STEP 2 · AI 검수 시작`을 추가했다. 하단 버튼을 제거하지 않고 동일한 버튼 요소·이동 핸들러·저장 확인 조건을 재사용한다. 새 의존성·상태·API는 추가하지 않았다.
- `type="button"`으로 업로드 form 제출을 방지한다. 저장 자료 없음에서는 숨기고, 저장 중 또는 저장 내역이 ready가 아닐 때 양쪽을 함께 잠근다. 부분 저장 중 사용 가능한 원본으로 진행하는 기존 규칙은 유지한다.
- 기존 녹색 버튼과 48px 높이를 유지하고 제목/작업 영역을 래핑한다. 768px 이하에서는 작업 버튼을 제목 다음 행으로 배치한다. UI/UX Pro Max의 두 검색 결과는 이번 배치와 직접 맞지 않아 사용하지 않았으며, 사용자 지정 위치·기존 토큰·일반적인 접근성 기준을 적용했다.
- UI-001/UI-003/A11Y-005 범위의 읽기 전용 검토를 반영했다. `npm run check`의 lint·format·typecheck·153개 테스트·production build 통과. 상·하단 동시 표시, 동일 이동, busy/loading/error/empty 상태, 업로드 form 미제출을 회귀 테스트했다. layout detector의 해당 TSX 경고는 없었다.
- 이번 수정의 새 브라우저 시각 QA 및 E2E 전체 실행은 하지 않았다. 로컬 페이지 응답 200을 확인했으며 실제 프로젝트/파일/인증/저장소는 변경하지 않았다.
