## 2. 업무 목적과 사용자가 원하는 흐름

건축 적산·물량산출 업무에서 산출서와 집계표를 등록하고, 관리자가 정한 검수 지침에 따라 기본 계산 검사와 Gemini AI 검토를 수행하여 근거가 남는 수량산출 분석표를 제공하는 회원 전용 업무 도구다.

`회원 로그인 → 프로젝트 생성/선택 → 자료 등록 완료 및 파일 목록 → AI 검수 → 원본 근거 확인 → 분석표 저장`

- 현재는 **웹 완성이 최우선**이다. Windows 설치형은 시험판이며 추가 개발을 우선하지 않는다.
- 클레임센터 스튜디오는 연동 방식 참고 프로젝트이지 이 저장소 자체가 아니다. ES 산출프로그램·거래명세표 원가관리의 업무 로직을 섞지 않는다.
- 설치형 UI 참고는 거래명세표 원가관리였지만, 사용자는 설치형 기능 불완전 때문에 웹부터 정상화하도록 지시했다.
- 관리자 지침은 버전·시험·승인·적용 이력으로 관리하고, 해당 프로젝트의 승인된 지침을 다른 직원도 동일하게 사용해야 한다. 브라우저 개인 설정만으로 처리하지 않는다.
- 건설사별 산출기준서를 첨부해 검수하는 기능은 **후속 확장**이다. 일반 검수부터 완성한다.
- 도면은 무거운 첨부자료로 고려하지만 원본 보관을 도면 의미 검수 완료로 표현하면 안 된다.
- 직원 정보는 기존 승인된 명단/계정 체계를 따른다. 임의 회원 생성·비밀번호 변경·명단 공개 금지.
- 저장 완료/실패를 한눈에 알 수 있어야 한다. 불필요한 단계·모순된 상태·반복 확인창을 늘리지 않는다.

## 3. 절대 바꾸면 안 되는 완료 기준

> 등록된 전체 자료에서 검수 대상이 빠짐없이 처리됐는가.

키 저장, 모델 목록 조회, 짧은 문장 생성, 일부 행의 AI 응답, 보고서 생성은 각각 중간 증거일 뿐 전체 검수 완료가 아니다.

- 등록 파일·시트·매핑·원본 행·활성 지침을 대조한다.
- pending/failed/unable/excluded/missing을 정상이나 0으로 처리하지 않는다.
- `not_flagged`는 정상 확정이 아니라 AI가 후보를 표시하지 않았다는 뜻이다.
- A=결정론적 계산, B=통계·패턴 후보, C=AI 문맥 후보를 분리한다. AI는 수량 수정·최종 승인 권한이 없다.
- 비교에는 확인된 부위·단위·범위·집계 의미가 필요하다. 산식·반올림·기준값을 추정해서 만들지 않는다.
- 원본/과거 실행/사람 판단은 보존한다. 재실행은 새 실행이고, 저장 재시도는 AI 재호출과 다르다.

### 우선순위 1 — 48KiB 초과 전체 교차비교

현재 큰 자료는 매 요청의 비교 문맥 한도에서 잘린다. 타깃 행은 나눠 처리할 수 있어도, **모든 자료 간 비교가 완료되는 것은 아니다.** `contextComplete` 가드를 삭제하거나 한도만 늘려 해결하지 말 것.

먼저 지침별 필요한 비교 범위와 원본 위치를 고정하고, 분할된 대상·비교 범위가 모두 처리됐다는 대조 기준을 설계한다. 산식 단독 검사와 자료 간 비교를 분리할 수 있지만, 자연어 지침의 범위를 임의 축소하지 않는다. 의미가 검증된 비교집단 없이 파일별로만 나누면 파일 간 중복을 놓칠 수 있다.

설계는 `docs/DECISION_LOG.md`에 기록하고 독립 검토 후 최소 구현한다. 경계 양쪽의 중복/상충, 한국어 큰 입력, 미매핑/제외, 빈 응답/중복 응답, 중단 후 재개, 이전 실행 불변을 합성 자료로 시험한다. 보류 자료를 완료로 만들지 않는다.
